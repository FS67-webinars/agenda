## Цель, результат и границы этапа

### Какую задачу я поставил

Я хотел получить законченную по основному содержанию учебную страницу Agenda — афишу событий в Израиле. На ней должны быть понятная шапка, первый экран с объяснением проекта, три карточки мероприятий, сведения о проекте и контакты. Пользователь должен понимать, куда нажимать и какую информацию он получит.

Для нас важен и способ реализации. Я выбрал простую структуру из HTML, собственного CSS, локального Bootstrap и уже подготовленных изображений. Каждый шаг должен быть достаточно небольшим, чтобы мы могли открыть его в истории Git и объяснить без догадок.

| Задача | Что получилось в рассматриваемой версии |
| --- | --- |
| Исправить навигацию | Пункты меню ведут к секциям этой страницы, логотипы — к её началу |
| Добавить первый экран | Появились фон набережной, заголовок, описание и ссылка на каталог |
| Заполнить каталог | В существующей сетке размещены три содержательные карточки |
| Сделать «Подробнее» полезным | У каждой карточки есть раскрываемый текст через HTML-элементы `details` и `summary` |
| Завершить нижнюю часть страницы | Добавлены логотип, блоки «О проекте» и «Контакты», строка с годом |

**Что я считаю выполненным по коду:** основные блоки статической страницы собраны, заглушки каталога заменены содержимым, ссылки имеют существующие цели, JavaScript приложения не добавлен.

**Что ещё нужно для окончательной приёмки:** согласовать внутреннее скругление изображений с рамкой карточки, проверить реальное отображение и клавиатурное управление в браузере, затем добавить этот документ в `docs` и ссылку на него в README. Ниже я точно отделяю подтверждённые результаты от проверок, которые ещё предстоит выполнить.

### Что означает «статическая страница»

Сейчас текст мероприятий непосредственно записан в `index.html`. Цвета, размеры и расположение определяются CSS. Изображения берутся из папки `images`.

При этом страница уже может реагировать на некоторые действия: браузер умеет переходить по ссылкам, раскрывать `details` и применять правила CSS при изменении ширины окна. Для этих возможностей собственный JavaScript не нужен.

В этот этап не входят покупка билетов, регистрация, отправка заявок, личный кабинет, поиск и фильтрация каталога. Я не добавляю в интерфейс элементы, которые обещали бы пользователю такие возможности без реализации.

### Как я отношусь к предварительному макету

Макет задаёт направление: светлая страница, фиолетовый акцент, фотография города, карточки и подвал. Реализованная учебная версия сохраняет эту композицию, но использует доступные на нашем этапе средства и существующие материалы.

Например, «Подробнее» реализовано через встроенное раскрытие HTML, а не через отдельные страницы мероприятий. В подвале сохранён реальный для группы способ связи — Teams. Это осознанные границы текущей учебной версии.

## Базовые понятия, которые понадобятся

Я возвращаюсь к этим понятиям перед разбором, потому что теоретическую часть на предыдущем занятии мы не успели пройти. Это опора для чтения коммитов, а не требование выучить всю таблицу наизусть.

### HTML описывает смысл, CSS — представление

В HTML я выбираю, чем является содержимое: заголовком, ссылкой, изображением, основным разделом или отдельной карточкой. В CSS задаю, как оно расположено и выглядит.

Bootstrap — заранее написанный CSS. Когда я добавляю `class="mb-3"`, браузер находит в подключённой библиотеке соответствующее правило. Само слово `mb-3` не имеет встроенного значения для HTML: значение появляется благодаря CSS.

Пользовательские классы с началом `agenda-` относятся к нашему проекту. Это удобное соглашение об именах, а не специальная команда браузеру.

### Почему у нас два CSS-файла

В HTML сохранён такой порядок:

```html
<link rel="stylesheet" href="./vendor/bootstrap.min.css">
<link rel="stylesheet" href="./style.css">
```

Я сначала подключаю библиотеку, затем собственные настройки. Так удобнее уточнять оформление готовых компонентов.

При этом неверно правило «последний файл всегда побеждает». Браузер учитывает каскад: среди прочего, важность объявления, применимость правила и специфичность селектора. Порядок в источнике решает конфликт сопоставимых объявлений после этих условий. Например, некоторые утилиты Bootstrap используют `!important`. Перемещение обычного правила ниже само по себе не гарантирует, что оно их перекроет.

### Селектор, класс, свойство и значение

В записи:

```css
.agenda-events {
    background-color: #f7f7fc;
}
```

`.agenda-events` — селектор: он выбирает элементы с этим классом. `background-color` — свойство, то есть настраиваемый признак. `#f7f7fc` — значение.

В HTML пишется `class="agenda-events"` без точки. Точка нужна в CSS, чтобы обозначить поиск по классу.

Если в HTML несколько классов, браузер применяет подходящие правила всех этих классов. Порядок слов в `class` обычно не решает конфликт стилей; его решает каскад CSS.

### Пользовательские CSS-свойства

В проекте уже была палитра:

```css
:root {
    --agenda-accent: #6425d0;
    --agenda-ink: #0d1633;
    --agenda-muted: #4c5268;
}
```

Я объясняю это так: мы даём значению понятное имя. `--agenda-accent` хранит акцентный цвет. Чтобы использовать значение, пишем `var(--agenda-accent)`.

`:root` выбирает корневой элемент документа; в нашем HTML это `html`. Обычные пользовательские свойства наследуются, поэтому палитра доступна вложенным элементам. Если нужное свойство переопределить на конкретном блоке, его новое значение действует в соответствующей области.

Это **CSS**, а не переменные JavaScript. В следующих коммитах таким именем мы обозначаем не только цвет, но и целый градиент.

### Отступы: внутренние, внешние и расстояния между колонками

| Запись | Как читаю | Что означает |
| --- | --- | --- |
| `padding` | Внутренний отступ | Пространство между содержимым и границей собственного блока |
| `margin` | Внешний отступ | Пространство снаружи границы блока |
| `py-3` | Padding по вертикали, значение 3 из шкалы | В стандартном Bootstrap — `1rem` сверху и снизу |
| `mb-2` | Margin снизу, значение 2 | `0.5rem` снизу |
| `mb-3` | Margin снизу, значение 3 | `1rem` снизу |
| `mb-4` | Margin снизу, значение 4 | `1.5rem` снизу |
| `py-5` | Padding по вертикали, значение 5 | `3rem` сверху и снизу |
| `g-3` | Gutters сетки по двум направлениям | Задаёт интервалы сетки величиной `1rem` |
| `gap-3` | CSS gap во flex/grid-контейнере | Задаёт промежуток между соседними элементами величиной `1rem` |

В стандартной шкале Bootstrap значения `0, 1, 2, 3, 4, 5` соответствуют `0, 0.25rem, 0.5rem, 1rem, 1.5rem, 3rem`. Число в конце класса не означает пиксели. Если размер шрифта корня равен 16 px, то `1rem` равен 16 px; при другом размере корня пересчёт меняется.

`g-3` и `gap-3` решают близкие задачи, но реализованы по-разному. В сетке Bootstrap расстояния организованы через внутренние отступы колонок и компенсирующие отрицательные внешние отступы строки; вертикальный интервал также связан с margin. Отрицательных padding в Bootstrap нет. `gap` — отдельное CSS-свойство контейнера. [Шкала отступов Bootstrap](https://getbootstrap.com/docs/5.3/utilities/spacing/) и [gutters](https://getbootstrap.com/docs/5.3/layout/gutters/).

### Flexbox: сначала определяю направление

В нашей шапке уже есть:

```html
<div class="container d-flex flex-column flex-md-row align-items-center justify-content-between gap-3">
```

`d-flex` включает flex-контейнер. По умолчанию здесь используется `flex-column`: дочерние элементы располагаются сверху вниз. Начиная с `md`, то есть с 768 CSS-пикселей ширины окна, `flex-md-row` располагает их в строку.

`justify-content` действует вдоль главной оси, а `align-items` — вдоль поперечной. Поэтому нельзя заучить, что первое свойство всегда выравнивает по горизонтали, а второе — по вертикали.

| Направление | Главная ось | `justify-content-between` | `align-items-center` |
| --- | --- | --- | --- |
| `flex-column` | Сверху вниз | Распределяет свободное место между элементами по вертикали, если оно есть | Центрирует элементы поперёк колонки |
| `flex-row` | Слева направо в нашей странице | Распределяет свободное место между элементами по горизонтали, если оно есть | Центрирует элементы по высоте строки |

В шапке `gap-3` дополнительно задаёт промежуток между логотипом и навигацией. Эти классы существовали до новых коммитов; я разбираю их, чтобы было понятно, на какую основу опирается продолжение.

### Действие 1. Добавляем цель для логотипа

Раньше было:

```html
<body>
```

Стало:

```html
<body id="top">
```

У ссылки логотипа уже стояло `href="#top"`. Теперь у неё появилась явно заданная цель.

`id` — уникальное имя конкретного элемента в этом документе. `href` — адрес перехода. Когда адрес начинается с `#`, браузер ищет фрагмент текущей страницы с соответствующим идентификатором.

Я проговариваю разницу: в `href="#top"` решётка означает переход к фрагменту, а в `id="top"` хранится само имя. Если написать `id="#top"`, мы создадим другое значение идентификатора.

Один `id` не нужно повторять на нескольких элементах. Несколько ссылок могут вести к одной цели — именно так позже будут работать логотипы шапки и подвала.

### Действие 2. Исправляем адреса меню

Было:

```html
<li class="nav-item"><a class="nav-link agenda-nav-link" href="index.html">Мероприятия</a></li>
<li class="nav-item"><a class="nav-link agenda-nav-link" href="events.html">О проекте</a></li>
<li class="nav-item"><a class="nav-link agenda-nav-link" href="contact.html">Контакты</a></li>
```

Стало:

```html
<li class="nav-item"><a class="nav-link agenda-nav-link" href="#events">Мероприятия</a></li>
<li class="nav-item"><a class="nav-link agenda-nav-link" href="#about">О проекте</a></li>
<li class="nav-item"><a class="nav-link agenda-nav-link" href="#contacts">Контакты</a></li>
```

`events.html` обозначает другой файл относительно текущего документа. `#events` обозначает часть текущего документа. Для одностраничной афиши нам подходит второй вариант.

В исходнике блоки `about` и `contacts` уже существовали в подвале. Я использую эти цели. В пятом коммите их идентификаторы будут перенесены с простых абзацев на полноценные секции, но значения останутся прежними — поэтому адреса меню не придётся снова менять.

Ссылка `index.html` существовала и раньше, но для пункта «Мероприятия» была слишком общей: она открывала документ, не обозначая переход именно к каталогу.

### Действие 3. Даём каталогу собственную секцию и имя

В этом коммите заголовок и существующую сетку помещаем внутрь:

```html
<section id="events" aria-labelledby="events-title">
    <h2 id="events-title">Future cards</h2>
```

Далее внутри идут прежние колонки; после них закрывается `section`. Это начало блока из реального коммита, а не полный фрагмент для вставки.

`section` объединяет тематическую часть документа. В нашем случае это каталог событий. `id="events"` нужен для перехода из меню. У заголовка отдельный идентификатор `events-title`.

`aria-labelledby="events-title"` сообщает вспомогательным технологиям: название этой секции нужно взять из текста указанного заголовка. Атрибут не выводит второй заголовок, не назначает цвет и не делает ссылку.

Я сравниваю две записи:

| Атрибут | Что находится внутри | Пример из страницы |
| --- | --- | --- |
| `aria-label` | Готовый текст названия | `aria-label="Основная навигация"` |
| `aria-labelledby` | Идентификатор элемента с названием | `aria-labelledby="events-title"` |

У `aria-labelledby` нет `#`. Слова `events-title` — не текст, который нужно произнести пользователю, а адрес элемента, текст которого используется как название. Атрибут `aria-label` у `nav` существовал до коммита; мы сохраняем его.

Английский `Future cards` пока остаётся. Первый шаг решает связь частей страницы; окончательный текст каталога появится в четвёртом коммите.

Было:

```html

```

Стало:


В прежнем варианте в слове `content` была лишняя `n`. Для человека ошибка почти незаметна; для браузера это другое имя класса.

Класс `nav` уже задаёт навигационному списку flex-расположение. `justify-content-center` добавляет центрирование содержимого по главной оси. В горизонтальной строке меню это горизонтальное центрирование в пределах доступного пространства.

Браузер не исправляет опечатки в именах классов и обычно не показывает из-за них красную ошибку на странице. Поэтому отсутствие ожидаемого эффекта я проверяю не только чтением CSS, но и точностью имени в HTML.

### Действие 5. Убираем дублирующую подпись логотипа

После изображения в ссылке раньше был видимый текст «Афиша мероприятий». Его убрали, а изображение получило уточнённый `alt` и размеры:

```html
<a class="logo-link" href="#top">
    <img class="logo-image" src="./images/agenda-logo.png"
        width="680" height="270" alt="Agenda — к началу страницы">
</a>
```

Я убираю повторяющуюся видимую подпись, сохраняя понятное назначение ссылки. Здесь изображение — единственное содержимое ссылки, поэтому `alt` помогает назвать не только картинку, но и действие: переход к началу страницы.

`src` указывает файл изображения. `./` означает текущую папку относительно HTML. Затем идёт папка `images` и имя файла.

`width="680"` и `height="270"` соответствуют исходным размерам логотипа. Они дают браузеру информацию о пропорциях ещё до полной загрузки картинки. Это не требование показывать логотип шириной 680 px: существующий CSS задаёт `width: 180px` и `height: auto`.

Если ширина отображения 180 px, пропорциональная высота составляет примерно 71,5 px. `max-width: 100%` ограничивает ширину доступным местом родителя. `display: block` у изображения, уже существовавший в CSS, убирает характерный для строчных изображений зазор под базовой линией текста.

### Действие 6. Уточняем оформление ссылки и отступы меню

В CSS добавлено:

```css
.logo-link {
    display: inline-block;
}
```

Ссылка остаётся элементом, который можно располагать в строке, но её содержимое оформляется как единый прямоугольный блок. Это удобно для изображения и рамки фокуса. `display` сам по себе не создаёт переход: переход по-прежнему задаётся `href`.

В существующее правило ссылки меню добавлено:

```css
.agenda-nav-link {
    --bs-nav-link-padding-x: 0.625rem;
    color: var(--agenda-ink);
    font-weight: 600;
}
```

`--bs-nav-link-padding-x` — пользовательское свойство, которое читает CSS компонента навигации Bootstrap. Оно задаёт горизонтальные внутренние отступы ссылки. При корневом размере 16 px значение `0.625rem` равно 10 px с каждой стороны.

Цвет и насыщенность 600 уже были в проекте. Новое действие здесь — уточнение горизонтального отступа, а не создание всей стилизации меню с нуля.

### Действие 7. Добавляем видимый фокус

```css
.logo-link:focus-visible,
.agenda-nav-link:focus-visible {
    outline: 2px solid var(--agenda-accent);
    outline-offset: 0.2rem;
}
```

Я объясняю фокус как текущую позицию клавиатурного управления. Нажимая `Tab`, человек переходит между интерактивными элементами. Ему нужно видеть, где он находится.

`:focus-visible` выбирает сфокусированный элемент в тех ситуациях, когда браузер считает необходимым показать индикатор фокуса; типичный пример — навигация с клавиатуры. Это не просто другое название `:hover`: наведение мыши и положение клавиатурного фокуса — разные состояния.

`outline` рисует внешнюю обводку. В записи `2px solid` указаны её толщина и сплошной стиль. `outline-offset` отодвигает обводку от границы элемента. Она не увеличивает размеры блока в потоке так, как могло бы добавление рамки.

Запятая между селекторами означает: одно правило применяется к обоим видам ссылок. В следующих коммитах к этой группе добавятся ссылка первого экрана и `summary`.

Подчёркивание и изменение цвета меню при наведении и фокусе существовали раньше. Теперь к ним добавлен отчётливый контур. [О `:focus-visible`](https://developer.mozilla.org/en-US/docs/Web/CSS/:focus-visible).

### Вопросы группе и ответы

1. **Чем `events.html` отличается от `#events`?** Первый адрес указывает на другой файл, второй — на фрагмент текущей страницы.
2. **Можно ли двум ссылкам дать `href="#top"`?** Да. Несколько ссылок могут иметь одну цель; сам `id="top"` должен быть уникальным.
3. **Почему браузер не применил `justify-contennt-center`?** В подключённом CSS нет ожидаемого правила с таким ошибочным именем.
4. **Почему размеры изображения в HTML не сделали логотип огромным?** Отображаемые размеры уточнены CSS; атрибуты также сообщают пропорции.
5. **Чем `aria-labelledby` отличается от `aria-label`?** Первое ссылается на текст другого элемента по его ID, второе содержит готовое название.
6. **Кому нужен видимый фокус, если всё можно нажать мышью?** Всем, кто управляет клавиатурой или другим устройством последовательной навигации.

### Ошибки, которые я показываю

Реальные исходные ошибки — опечатка в классе и неверные адреса пунктов меню. Учебный пример для отдельной демонстрационной копии — временно написать `href="#event"`, оставив `id="events"`. Пропавшая буква разрывает соответствие. Для исправления нужно согласовать имена, а не менять цвет ссылки или добавлять JavaScript.

```html
<main>
```

Почему я убираю `container` с общего `main`? Если ограничить ширину всей основной области, внутри неё окажется ограничен и фон первого экрана. Нам нужна другая структура: секция может занимать всю доступную ширину страницы, а текст внутри неё остаётся в аккуратном контейнере.

Новый блок записан так:

```html
<section class="agenda-hero" aria-labelledby="hero-title">
    <div class="container">
        <div class="agenda-hero-copy">
            <h1 id="hero-title" class="mb-3">Город начинается с&nbsp;событий</h1>
            <p class="mb-4">Концерты, выставки и встречи в Израиле. Найдите повод провести вечер в городе.</p>
            <a class="btn agenda-hero-link" href="#events">Смотреть мероприятия</a>
        </div>
    </div>
</section>
```

Снаружи `section.agenda-hero` отвечает за общий фон и вертикальное пространство. Внутри `.container` ограничивает содержимое по стандартным правилам Bootstrap и выравнивает его относительно остальных частей страницы. Внутри контейнера `.agenda-hero-copy` дополнительно ограничивает ширину именно текстовой группы.

Это три разные задачи. Их разделение позволяет менять фон, общую ширину страницы и длину строки независимо.

Каталог на этом промежуточном этапе получает `class="container py-4"` на своей секции:

```html
<section class="container py-4" id="events" aria-labelledby="events-title">
```

Так он сохраняет прежнее ограничение ширины и вертикальные отступы, хотя `main` больше их не задаёт. В четвёртом коммите и каталог получит собственную внешнюю секцию с внутренним контейнером.

### Действие 2. Добавляем главный заголовок и объяснение проекта

`h1` — основной заголовок страницы. В итоговом документе он один. Названия крупных разделов используют `h2`, а названия мероприятий — `h3`.

`aria-labelledby="hero-title"` связывает первый экран с его заголовком по той же схеме, которую мы разобрали в первом коммите.

В тексте `с&nbsp;событий` используется неразрывный пробел. Я соединяю короткий предлог «с» со следующим словом, чтобы он не оставался один в конце строки. Это не запрет переносов для всего заголовка: остальные подходящие места переноса сохраняются.

`mb-3` у заголовка и `mb-4` у абзаца задают внешние отступы снизу. Я не добавляю пустые абзацы или несколько `<br>` ради расстояния. Содержание остаётся в HTML, расстояние задаётся CSS.

### Действие 3. Настраиваем фоновое изображение и подложку

Добавленный CSS:

```css
.agenda-hero {
    --agenda-hero-overlay: linear-gradient(180deg, #faf9ff, rgba(250, 249, 255, 0.93) 58%, rgba(250, 249, 255, 0.2));
    padding: 3rem 0 7rem;
    background-color: #faf9ff;
    background-image: var(--agenda-hero-overlay), url("./images/hero-tel-aviv.png");
    background-position: 68% center;
    background-size: cover;
}
```

#### Почему фон в CSS, а не картинка внутри текста

На первом экране изображение создаёт атмосферу; название и смысл проекта уже передаются текстом. Поэтому оно используется как декоративный фон секции. Для такого фона нет HTML-атрибута `alt`.

У карточек другая задача: изображение относится к конкретному мероприятию и находится в его структуре. Там применяется `img` с осмысленным `alt`.

Если важная информация присутствовала бы только на фоновой картинке, её пришлось бы продублировать доступным текстом. В нашей реализации заголовок, описание и действие остаются обычным HTML.

#### Как читается `padding: 3rem 0 7rem`

У сокращённой записи три значения:

- `3rem` — сверху;
- `0` — справа и слева;
- `7rem` — снизу.

При корневом размере 16 px это 48 px сверху и 112 px снизу. Большой нижний отступ оставляет место для изображения под текстом на узком экране. Высота секции складывается из содержимого и отступов; фиксированная высота здесь не задана.

Ноль по горизонтали относится именно к внешней секции. Горизонтальные отступы внутреннего контейнера продолжают работать.

#### Для чего однотонный фон

`background-color: #faf9ff` задаёт светлый базовый цвет. Он находится под фоновыми изображениями и виден, например, пока фотография ещё не загрузилась.

#### Как работают два слоя

В `background-image` через запятую указаны:

1. Градиент из `--agenda-hero-overlay`.
2. Фотография из `hero-tel-aviv.png`.

Первый перечисленный слой рисуется выше последующих. Поэтому светлый градиент лежит поверх фотографии и помогает читать тёмный текст.

Если перепутать порядок, непрозрачная фотография может закрыть подложку. Если вместо этого поставить `opacity` на всю секцию, прозрачнее станет не только фон, но и её содержимое. Для нашей задачи прозрачность задаётся внутри цветов градиента.

#### Что означают числа в градиенте

`linear-gradient` создаёт плавный переход цветов. `180deg` направляет его сверху вниз. В начале используется светлый непрозрачный цвет. К отметке 58% задан светлый цвет с альфа-значением 0,93 — то есть с непрозрачностью 93%, а к концу — с альфой 0,2.

В `rgba(250, 249, 255, 0.93)` первые три числа задают составляющие цвета, последнее — альфа-значение: 1 означает непрозрачный цвет, 0 — полностью прозрачный. Таким образом, в верхней зоне фотография сильнее прикрыта светлым слоем, а ниже заметнее.

Градиент здесь хранится в пользовательском CSS-свойстве целиком. На широком экране мы заменим значение свойства, сохранив общий механизм подключения фона.

#### Что делает `cover`

`background-size: cover` увеличивает или уменьшает изображение с сохранением пропорций так, чтобы закрыть всю область фона. Если форма области и фотографии различается, часть фотографии выходит за пределы видимой области и обрезается.

Это ожидаемое поведение. «Заполнить всю область» не равно «показать каждый край фотографии». Для первого экрана мы предпочитаем сплошной фон.

#### Как понимать `background-position: 68% center`

Второе значение центрирует фон по вертикали. Первое управляет горизонтальным положением и помогает выбрать видимую часть фотографии при обрезке.

Технически 68% изображения совмещаются с 68% области позиционирования фона. Это **не** команда поместить левый край картинки на 68% ширины секции. При `cover` такая настройка меняет кадрирование; заметность изменения зависит от того, есть ли по соответствующей оси лишняя часть изображения.

Я показываю этот принцип временным изменением значения в инструментах браузера, когда визуальная проверка будет доступна. [Пояснение MDN о background-position](https://developer.mozilla.org/en-US/docs/Web/CSS/background-position).

### Действие 4. Ограничиваем длину строки

```css
.agenda-hero-copy {
    max-width: 34rem;
}
```

`max-width` задаёт верхний предел ширины, а не жёсткую ширину. При корневом размере 16 px предел равен 544 px. Если доступное место меньше, блок может стать уже.

Для абзаца установлен более узкий предел:

```css
.agenda-hero p {
    max-width: 28rem;
    color: var(--agenda-muted);
    font-size: 1.125rem;
}
```

При той же условной базе это ширина не больше 448 px и шрифт 18 px. Более короткую строку удобнее читать на фоне изображения. Цвет берётся из существующей палитры.

Селектор `.agenda-hero p` выбирает абзацы внутри первого экрана. Пробел означает отношение вложенности; это не два независимых селектора через запятую.

### Действие 5. Делаем крупный, но ограниченный заголовок

```css
.agenda-hero h1 {
    font-size: clamp(2.25rem, 1.6rem + 3.2vw, 4rem);
    font-weight: 750;
    line-height: 1.06;
    letter-spacing: -0.035em;
}
```

#### Разбираем `clamp` по шагам

Я читаю `clamp` как «выбрать желаемое значение, но удержать его между минимумом и максимумом»:

- `2.25rem` — нижняя граница.
- `1.6rem + 3.2vw` — желаемый размер, зависящий от ширины окна.
- `4rem` — верхняя граница.

`vw` — единица, связанная с шириной области просмотра: `1vw` составляет 1% её ширины. `rem` связан с размером шрифта корневого элемента.

Если условно принять корневой размер 16 px, получим минимум 36 px и максимум 64 px. Желаемая часть равна `25.6px + 3.2% ширины окна`.

| Ширина окна | Желаемое значение | Итог после ограничения |
| --- | --- | --- |
| 320 px | 25,6 + 10,24 = 35,84 px | 36 px: сработал минимум |
| 390 px | 25,6 + 12,48 = 38,08 px | 38,08 px |
| 992 px | 25,6 + 31,744 = 57,344 px | 57,344 px |
| 1440 px | 25,6 + 46,08 = 71,68 px | 64 px: сработал максимум |

Таблица объясняет вычисление, а не заменяет измерение в браузере при реальных настройках шрифта. Такая запись корректна в CSS; внутри математической функции `clamp` отдельная оболочка `calc` для этой суммы не обязательна. JavaScript здесь не используется. [MDN: clamp()](https://developer.mozilla.org/en-US/docs/Web/CSS/clamp).

#### Остальные свойства заголовка

`font-weight: 750` задаёт насыщенность. Это допустимое числовое значение. Если выбранный шрифт не имеет именно такого начертания, браузер подбирает доступное по правилам работы со шрифтами. Поэтому 750 не гарантирует визуально отдельную толщину между 700 и 800 в любой системе.

`line-height: 1.06` задаёт высоту строки как множитель размера шрифта. Например, при размере 50 px значение соответствует 53 px. Это компактный интерлиньяж для крупного заголовка.

`letter-spacing: -0.035em` немного уменьшает расстояние между буквами. Здесь `em` отсчитывается от размера шрифта самого элемента. При 50 px поправка составляет −1,75 px. Значение отрицательное, потому что расстояние уменьшаем.

Я использую эти настройки вместе, чтобы заголовок был выразительным и занимал предсказуемое место. Отдельно проверяю, что он остаётся читаемым и не обрезается.

### Действие 6. Оформляем ссылку как кнопку

В HTML:

```html
<a class="btn agenda-hero-link" href="#events">Смотреть мероприятия</a>
```

Я оставляю элемент `a`, потому что действие — переход к каталогу. Класс `btn` даёт оформление кнопки, но не меняет семантику HTML: элемент остаётся ссылкой.

`agenda-hero-link` содержит наши настройки компонента:

```css
.agenda-hero-link {
    --bs-btn-color: #fff;
    --bs-btn-bg: var(--agenda-accent);
    --bs-btn-border-color: var(--agenda-accent);
    --bs-btn-hover-color: #fff;
    --bs-btn-hover-bg: #501eaa;
    --bs-btn-hover-border-color: var(--bs-btn-hover-bg);
    --bs-btn-active-color: #fff;
    --bs-btn-active-bg: var(--bs-btn-hover-bg);
    --bs-btn-active-border-color: var(--bs-btn-hover-bg);
    --bs-btn-focus-shadow-rgb: 100, 37, 208;
    --bs-btn-padding-x: 1.25rem;
    --bs-btn-padding-y: 0.7rem;
    --bs-btn-font-weight: 600;
    --bs-btn-border-radius: 0.6rem;
}
```

Я объясняю свойства группами, потому что они настраивают разные состояния одного элемента.

| Группа | Что задаёт | Зачем |
| --- | --- | --- |
| `--bs-btn-color`, `--bs-btn-bg`, `--bs-btn-border-color` | Цвет текста, фон и рамку обычного состояния | Белая надпись на фиолетовом фоне |
| `--bs-btn-hover-*` | Внешний вид при наведении | Фон становится темнее, белый текст сохраняется |
| `--bs-btn-active-*` | Оформление активного нажатия | Не допускаем случайного возврата к неподходящим стандартным цветам |
| `--bs-btn-focus-shadow-rgb` | RGB-компоненты тени фокуса компонента | Согласуем её с фиолетовым акцентом |
| `--bs-btn-padding-x` и `--bs-btn-padding-y` | Внутренние отступы | Делаем область ссылки удобной по размеру |
| `--bs-btn-font-weight` | Насыщенность текста | Выделяем действие |
| `--bs-btn-border-radius` | Радиус углов | Получаем мягкое скругление |

При корневом размере 16 px горизонтальный padding составляет 20 px, вертикальный — 11,2 px, радиус — 9,6 px.

`var(--bs-btn-hover-bg)` повторно использует выбранный цвет наведения. Если мы поменяем этот цвет, зависящие от него значения останутся согласованными.

`--bs-btn-focus-shadow-rgb` содержит именно три цветовых компонента, потому что Bootstrap использует их внутри своего выражения цвета тени. Это не самостоятельное обычное свойство `box-shadow`.

Новые имена переменных не заменяют класс `btn`. В проекте нужен потребитель этих значений — правила Bootstrap, применённые к элементу с `btn`. Если оставить только `agenda-hero-link`, заданные `--bs-btn-*` сами не создадут оформление кнопки. [Bootstrap: Buttons](https://getbootstrap.com/docs/5.3/components/buttons/).

В существующее общее правило фокуса также добавлено `.agenda-hero-link:focus-visible`. Поэтому ссылка получает такой же отчётливый внешний контур, как меню и логотип.

### Действие 7. Меняем композицию на широком окне

```css
@media (min-width: 992px) {
    .agenda-hero {
        --agenda-hero-overlay: linear-gradient(90deg, #faf9ff 3%, rgba(250, 249, 255, 0.96) 30%, rgba(250, 249, 255, 0.84) 47%, rgba(250, 249, 255, 0) 78%);
        padding-block: 5rem;
        background-position: center;
    }
}
```

`@media` задаёт условие применения правил. `min-width: 992px` означает: ширина области просмотра **не меньше** 992 CSS-пикселей. Правило действует и при ровно 992 px, и при большей ширине.

До этой границы работает базовая композиция: градиент сверху вниз и более крупный нижний отступ. Начиная с 992 px градиент направлен слева направо — `90deg`. Слева остаётся светлая область под текстом, справа прозрачность увеличивается и лучше видно город.

Проценты 3, 30, 47 и 78 задают расположение цветовых остановок. Это не ширины HTML-колонок.

`padding-block: 5rem` задаёт отступы по блочной оси. При обычном горизонтальном письме нашей страницы это верхний и нижний отступы: по 80 px при корневом размере 16 px. Горизонтальный нулевой padding из базового правила остаётся.

`background-position: center` возвращает центрирование фона по обеим осям. Условие 992 px совпадает с границей Bootstrap `lg`; так изменения композиции первого экрана согласованы с переходом каталога к трём колонкам.

### Что получили

Вместо немедленного перехода от шапки к заглушкам появился вводный блок с главным заголовком, коротким обещанием пользы и действующей ссылкой на каталог. Фон и текст имеют разные ограничения ширины, а CSS описывает две композиции для разных размеров окна.

Каталог на этом шаге ещё не наполнен: там по-прежнему три заготовки. Промежуточный коммит решает задачу первого экрана целиком, не смешивая её с устройством карточек.

### Как я проверяю понимание

1. **Почему `container` находится внутри секции?** Чтобы фон мог занимать всю ширину, а содержимое — оставаться ограниченным и выровненным.
2. **Почему фотография может обрезаться при `cover`?** Так сохраняются пропорции и заполняется вся область с другим соотношением сторон.
3. **Какой слой из `background-image` расположен сверху?** Первый в списке — наш градиент.
4. **Почему нельзя сделать весь первый экран полупрозрачным через `opacity` ради читаемости?** Тогда прозрачность затронет и текст с действием; нам нужна прозрачность фонового слоя.
5. **Что произойдёт с размером заголовка на очень широком окне?** `clamp` удержит его на верхней границе `4rem`.
6. **Почему элемент с видом кнопки записан как ссылка?** Его назначение — переход к другой части документа.
7. **На ширине ровно 992 px медиазапрос уже действует?** Да: `min-width` включает указанную границу.

### Учебные ошибки и проверка

В демонстрационной копии можно временно убрать `btn`, перепутать слои фона или заменить `max-width` текстового блока на слишком большую фиксированную ширину. Я каждый раз прошу группу сначала предсказать результат, потом проверить его и вернуть исходный код.

Для приёмки нужно посмотреть узкое и широкое окно: читается ли весь текст, не выпадает ли ссылка, удачно ли кадрируется фотография, заметен ли фокус. Эти свойства нельзя окончательно подтвердить одним чтением CSS; фактический статус проверки приведён ниже.

### Кто за что отвечает: колонка, карточка и её содержимое

> «Представьте полку с коробками. Сначала нужно определить, сколько места занимает каждая коробка на полке. Затем — как устроена сама коробка и как внутри неё размещены предметы. В нашем коде это разные уровни».

| Уровень | Его задача в нашем коде |
| --- | --- |
| `.container` | Ограничивает общую ширину содержимого раздела и даёт боковые поля. |
| `.row.g-3` | Организует строку сетки с переносом колонок и промежутками. |
| `.col-12.col-md-6.col-lg-4` | Определяет, какую часть строки занимает карточка на данной ширине окна. |
| `article.card.agenda-card.h-100` | Содержит одно мероприятие, получает рамку, фон, скругление и высоту. |
| `.card-body.d-flex.flex-column` | Располагает текстовые части внутри карточки по вертикали. |

Внешняя сетка уже была до этого коммита. Здесь я сохраняю её и меняю содержимое первой колонки. `article` выбран потому, что карточка описывает отдельное событие: у неё есть собственные название, время и описание. Имя тега сообщает смысл, а классы задают оформление.

`card` — готовый компонент Bootstrap. `agenda-card` — наше дополнение к нему. Имена с `agenda-` не встроены в браузер и Bootstrap: они начинают работать благодаря нашему `style.css`. Наличие двух классов не создаёт два HTML-элемента; один элемент получает правила из обоих наборов.

### Почему название записано как `h3`, хотя есть класс `h5`

```html
<h3 class="card-title h5 fw-bold">Джазовый концерт в Тель-Авиве</h3>
```

Я выстраиваю иерархию: `h1` — основная тема страницы, `h2` — каталог, `h3` — отдельное мероприятие внутри каталога. Класс `h5` даёт заголовку Bootstrap-оформление меньшего размера. Он не превращает тег в `h5` и не меняет уровень заголовка для средств доступности.

`card-title` задаёт оформление заголовка карточки, в частности предусмотренный компонентом нижний отступ. `fw-bold` явно задаёт жирное начертание. Если текст выглядит слишком крупным, я меняю оформление, а не выбираю случайный уровень HTML-заголовка только ради размера.

### Изображение: адрес, описание и пропорции

`src="./images/event-jazz.png"` указывает файл относительно `index.html`. Изображение уже существовало в проекте: в этом коммите его подключили к карточке, а не создали заново.

`alt` описывает значимое содержание фотографии. Он помогает понять картинку, когда она недоступна визуально. Фраза «картинка концерта» дала бы меньше информации, чем конкретное описание музыкантов. Здесь фотография является содержимым карточки, поэтому используется `<img>`. Изображение набережной в первом экране используется как CSS-фон для оформления; это другой способ включения графики.

Атрибуты `width="1672"` и `height="941"` соответствуют размерам исходного файла и помогают браузеру заранее определить его пропорции. Они не требуют показывать фотографию на странице шириной 1672 пикселя: CSS задаёт отображаемые размеры.

Класс `card-img-top` растягивает изображение по ширине карточки и оформляет верхние углы. Наш класс добавляет:

```css
.agenda-card-image {
    height: auto;
    aspect-ratio: 16 / 9;
    object-fit: cover;
}
```

Разбираю по шагам:

- **Ширину** изображение получает от карточки через Bootstrap.
- **`height: auto`** позволяет вычислить высоту, а не зафиксировать её отдельным числом.
- **`aspect-ratio: 16 / 9`** задаёт предпочтительные пропорции области изображения: на 16 частей ширины приходится 9 частей высоты. При вычисляемой высоте и ширине 320 CSS-пикселей такая область имеет высоту 180 пикселей.
- **`object-fit: cover`** определяет, как сама фотография заполняет выделенную область: сохраняет пропорции, заполняет её целиком, при необходимости обрезает края.

Это два разных вопроса: `aspect-ratio` помогает определить форму области, а `object-fit` размещает изображение внутри неё. Здесь нет правила `height: 210px`. Когда колонка меняет ширину, высота фотографии тоже должна меняться. Если одновременно жёстко задать обе стороны, `aspect-ratio` уже не сможет вычислять свободную сторону таким способом.

Справка: [MDN — aspect-ratio](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/aspect-ratio).

### Текст, дата и интервалы

Категория «Музыка» — обычный абзац, оформленный собственным классом. Это пока не кнопка фильтра. От нажатия на неё не должно ожидаться никакого действия.

В строке времени есть два представления одной информации:

```html
<time datetime="2026-12-04T20:00">4 декабря, 20:00</time>
```

Человек видит удобную русскую запись. Атрибут `datetime` содержит дату и время в формальном виде: год, месяц, день, букву `T`, часы и минуты. Сам тег не запускает таймер и не переводит время в часовой пояс посетителя. Смещение часового пояса здесь не указано; далее в каталоге появится пояснение о местном времени Израиля. Это учебные данные, а не подтверждённое расписание реального концерта.

`card-text` обозначает текстовую часть компонента. Классы отступов читаю как короткие команды: `m` — внешний отступ, `p` — внутренний; `t` — сверху, `b` — снизу. Число — номер значения в шкале Bootstrap. Поэтому `mb-3` — нижний внешний отступ `1rem`, а не 3 пикселя; `mb-2` и `mt-2` — `0.5rem`, `mb-0` — ноль. При корневом размере шрифта 16 пикселей `1rem` соответствует 16 пикселям, но это условие, а не универсальная константа.

### Почему «Подробнее» держится у нижней части карточки

Здесь работает цепочка из нескольких правил:

```html
<article class="card agenda-card h-100">
    ...
    <div class="card-body d-flex flex-column">
        ...
        <details class="agenda-card-details mt-auto pt-3">
```

В этом коротком фрагменте многоточия обозначают только пропущенное поясняемое содержимое; полный код выше дан без пропусков.

`h-100` означает высоту `100%` относительно родительской области. В существующей flex-сетке Bootstrap колонки одной строки растягиваются по высоте строки, а карточка заполняет свою колонку. Это помогает выровнять карточки внутри одного ряда. Оно не задаёт одинаковую фиксированную высоту всем карточкам во всех рядах страницы.

`card-body` имеет внутренние отступы и возможность занимать оставшееся место внутри карточки. `d-flex` делает тело карточки flex-контейнером. `flex-column` направляет его главную ось сверху вниз. Непосредственные дочерние элементы — категория, заголовок, дата, описание и `details` — располагаются по этой оси.

`mt-auto` у `details` означает автоматический верхний внешний отступ. Если в теле карточки есть свободное вертикальное место, этот отступ занимает его и отодвигает подробности вниз. Если места нет, огромный зазор не возникает. Это не `position: absolute`: блок остаётся в обычной структуре и при раскрытии может увеличивать высоту карточки.

`pt-3` создаёт внутренний отступ над содержимым `details`. Разделительная линия находится на верхней границе блока, поэтому между линией и словом «Подробнее» остаётся пространство. Автоматический `margin` располагается снаружи границы; `padding` — внутри. Эти отступы решают разные задачи.

### Почему подробности работают без JavaScript

> «Я использую готовую возможность HTML. Браузер уже знает, как раскрывать `details`. Нам нужно правильно описать его содержимое и оформить элемент».

`details` — раскрываемая область. Её первый элемент `summary` — видимая подпись, которой управляют раскрытием. Следующий абзац становится видимым в открытом состоянии. Атрибута `open` здесь нет, поэтому исходное состояние закрыто. Для первоначально открытого состояния был бы нужен `open`; запись `open="false"` всё равно означала бы наличие логического атрибута, а не закрытие.

В коде отсутствуют `onclick`, собственный JS и Bootstrap JS bundle. Это не компонент Bootstrap Collapse: работой раскрытия управляет сам браузер. Для проверки нужно попробовать мышь и клавиатуру: перейти к `summary` клавишей `Tab`, затем проверить раскрытие и закрытие клавишами `Enter` и пробелом в используемом браузере.

Внутри подписи есть:

```html
<summary>Подробнее<span class="visually-hidden"> о джазовом концерте</span></summary>
```

`span` выделяет фрагмент текста без самостоятельного заголовка или абзаца. `visually-hidden` скрывает уточнение визуально, сохраняя его для вспомогательных технологий. Благодаря этому подпись содержит более точное название действия: «Подробнее о джазовом концерте». Пробел перед «о» оставлен внутри `span`, чтобы слова не слиплись. Замена на `display: none` убрала бы текст и из обычного представления для средств доступности.

Справки: [MDN — details](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/details), [Bootstrap — Visually hidden](https://getbootstrap.com/docs/5.3/helpers/visually-hidden/).

### Полный новый блок CSS карточки

```css
.agenda-card {
    --bs-card-color: var(--agenda-ink);
    --bs-card-border-color: #e4dff1;
    --bs-card-border-radius: 0.9rem;
    box-shadow: 0 0.4rem 1.2rem rgba(13, 22, 51, 0.08);
}

.agenda-card-image {
    height: auto;
    aspect-ratio: 16 / 9;
    object-fit: cover;
}

.agenda-card-category {
    color: var(--agenda-accent);
    font-size: 0.875rem;
    font-weight: 700;
}

.agenda-card-meta {
    color: var(--agenda-muted);
    font-size: 0.875rem;
}

.agenda-card-details {
    border-top: 1px solid var(--bs-card-border-color);
}

.agenda-card-details summary {
    color: var(--agenda-accent);
    cursor: pointer;
    font-weight: 600;
}

.agenda-card-details summary:hover {
    text-decoration: underline;
}
```

Первые три свойства `.agenda-card` настраивают параметры Bootstrap-карточки: цвет текста, цвет границы и внешний радиус скругления. Например, `var(--agenda-ink)` берёт значение уже объявленного цвета проекта. Само имя переменной не рисует элемент: её значение используют обычные CSS-правила компонента `.card`.

`box-shadow` задаёт тень: первый ноль — отсутствие горизонтального смещения, `0.4rem` — смещение вниз, `1.2rem` — размытие. В `rgba(13, 22, 51, 0.08)` три первых числа задают цвет, последнее — непрозрачность 8%. Это лёгкое отделение карточки от фона без изменения ширины колонки.

Категория получает акцентный цвет, размер `0.875rem` и насыщенность `700`. Строка даты получает тот же размер, но приглушённый цвет. Размер `0.875rem` равен 14 пикселям при корневых 16 пикселях. Значения `700` и `600` относятся к насыщенности шрифта; фактическое начертание зависит от доступного шрифта.

`border-top` задаёт линию толщиной 1 пиксель, сплошного типа и цвета рамки карточки. Переменная цвета доступна вложенному `details` благодаря наследованию пользовательских свойств. Селектор `.agenda-card-details summary` выбирает `summary` внутри нашего блока подробностей. Пробел между частями селектора означает связь «потомок».

`cursor: pointer` меняет вид указателя. Оно само не делает элемент работающим: раскрытие даёт HTML-элемент. `:hover` добавляет подчёркивание при наведении.

Кроме этого блока, `summary` включён в уже существующее общее правило фокуса:

```css
.logo-link:focus-visible,
.agenda-nav-link:focus-visible,
.agenda-hero-link:focus-visible,
.agenda-card-details summary:focus-visible {
    outline: 2px solid var(--agenda-accent);
    outline-offset: 0.2rem;
}
```

Запятые объединяют несколько независимых селекторов. В этом коммите к списку добавлена последняя строка. `:focus-visible` позволяет показать рамку, когда браузер считает необходимым визуально обозначить фокус, в частности при клавиатурной навигации. `outline-offset` отодвигает её от края элемента. Рамка фокуса не заменяет нижнее подчёркивание при наведении: это обратная связь для другого способа управления.

### Что получили и как это проверить

По коду подтверждается: первая заготовка заменена полноценным событием, подключена существующая фотография, появились название, категория, время, описание и нативные подробности. Новые стили пригодны для повторного использования.

Для демонстрации я проверяю ожидаемый результат в браузере: фотография сохраняет пропорции при сужении окна, длинный заголовок переносится, «Подробнее» раскрывает содержательный текст, а при переходе клавишей `Tab` видна позиция фокуса. Затем раскрываю подробности и смотрю, что содержимое не обрезалось. Это сценарий предстоящей браузерной проверки; чтение HTML/CSS само по себе не подтверждает, что такой прогон уже выполнен.

### Вопросы группе и ответы

1. **Какой элемент отвечает за количество карточек в ряду?** Внешняя колонка с `col-*` вместе с `.row`; не фотография и не заголовок.
2. **Почему `h3` с классом `h5` остаётся третьим уровнем заголовка?** Семантический уровень определяет тег, класс меняет оформление.
3. **Какая высота получится при ширине области изображения 400 пикселей и отношении 16:9?** 225 пикселей, если высота вычисляется по этому отношению и её не ограничивают другие правила.
4. **Что случится с `mt-auto`, если убрать flex-контейнер у тела карточки?** Исчезнет описанный механизм распределения свободного пространства по вертикальной главной оси; прежнее выравнивание нельзя будет ожидать.
5. **Кто открывает подробности, если JS не подключён?** Браузер, поскольку это встроенное поведение `details`/`summary`.
6. **Создаёт ли `datetime` запись в календаре?** Нет. Он обозначает дату в машинно-читаемом формате.
7. **Для чего скрытая часть подписи?** Чтобы название действия оставалось содержательным для вспомогательных технологий, особенно когда рядом несколько одинаковых «Подробнее».

### Ошибки, которые показываю на учебной копии

| Учебная ошибка | Как её распознать | Что исправить |
| --- | --- | --- |
| Вставить карточку внутрь старого `p-3 border bg-light` | Лишняя рамка и увеличенные поля | Заменить старую заготовку целиком. |
| Поставить классы сетки на случайный внутренний абзац | Текст получает ширину колонки, а карточки не выстраиваются | Вернуть `col-*` внешним непосредственным детям `.row`. |
| Написать `scr` вместо `src` | Фотография не загружается | Проверить имя атрибута и путь. Это учебный пример, не ошибка данного коммита. |
| Задать картинке несогласованные фиксированные ширину и высоту без нужного размещения | Фотография выглядит растянутой или меняет предполагаемый кадр | Проверить размеры области и `object-fit`. |

### Действие 5. Объясняю, почему сетка меняет число колонок

```html
<div class="row g-3">
    <div class="col-12 col-md-6 col-lg-4">
        <!-- Одна карточка мероприятия -->
    </div>
</div>
```

Это сокращённая схема для объяснения вложенности; в реальном файле внутри `.row` три колонки. [Сетка Bootstrap](https://getbootstrap.com/docs/5.3/layout/grid/) делит ширину ряда на 12 условных долей.

| Ширина окна | Действующее правило | Доля одной карточки | Результат для трёх карточек |
|---|---|---|---|
| Меньше `768px` | `col-12` | `12/12`, вся ширина ряда | Три карточки друг под другом |
| От `768px` до значения меньше `992px` | `col-md-6` | `6/12`, половина ряда | Две карточки в первом ряду, третья в следующем |
| От `992px` | `col-lg-4` | `4/12`, треть ряда | Три карточки в одном ряду |

> «Мы не проверяем название устройства. Мы смотрим на доступную ширину окна. Даже на большом мониторе узкое окно браузера должно получить вариант с одной колонкой».

Классы с `md` и `lg` начинают действовать **от** своих порогов. Правило `col-md-6` само не выключается на `992px`; на этой ширине более позднее правило для `lg` задаёт новую ширину. `g-3` задаёт горизонтальные и вертикальные промежутки сетки размером `1rem`. Bootstrap реализует их через свои правила для ряда и колонок, поэтому произвольно переставлять `.row` и `.col-*` местами нельзя.

Внутри карточки сохраняются `h-100`, `d-flex flex-column` и `mt-auto`. Они решают другую задачу: карточка заполняет высоту своей колонки, её тело располагает содержимое вертикально, а блок подробностей использует свободное место над собой. Эти классы не задают число карточек в строке.

### Действие 5. Добавляю завершающую строку и CSS

```html
<p class="agenda-footer-year mt-4 pt-3 mb-0">Agenda · 2026</p>
```

```css
.agenda-footer {
    background-color: #f5f0ff;
    border-top: 1px solid #ded5f1;
}

.agenda-footer p {
    color: var(--agenda-muted);
}

.agenda-footer-year {
    border-top: 1px solid #ded5f1;
    font-size: 0.875rem;
}
```

Первая верхняя граница отделяет весь подвал от каталога. Вторая находится у абзаца с годом и отделяет завершающую строку от основных сведений. `border-top: 1px solid ...` читаем как «верхняя граница толщиной один пиксель, сплошная, указанного цвета».

В селекторе `.agenda-footer p` пробел означает потомка: правило выбирает все абзацы внутри элемента с классом `agenda-footer`, даже если между ними есть дополнительные контейнеры. Это не правило для всех абзацев страницы.

`mt-4` создаёт внешний промежуток перед абзацем с годом; `pt-3` добавляет внутреннее пространство между его верхней границей и текстом; `mb-0` убирает нижний внешний отступ. На этом примере я предлагаю увидеть разницу между `margin` и `padding`: они располагаются с разных сторон границы элемента. `font-size: 0.875rem` делает завершающую строку немного меньше основного текста.

### Как показываю этот коммит в VS Code

1. В `index.html` нахожу `<footer` и раскрываю весь блок до `</footer>`.
2. Показываю три непосредственных блока внутри `.row`, затем отдельный абзац с годом после ряда.
3. Нахожу `href="#about"` в меню и `id="about"` в подвале. Аналогично сверяю контакты и переход к началу страницы.
4. В `style.css` рассматриваю три добавленных правила. Временно подсвечиваю отдельно `margin`, `border` и `padding` в инструментах разработчика браузера, если провожу живую демонстрацию.
5. В терминале читаю изменение командой `git show 10d5c6e -- index.html style.css`.

### Что получил и как предлагаю проверить

**Результат по коду:** подвал содержит логотип, описание проекта, контактный канал Teams и год. Меню связано с именованными разделами. Шапка, каталог и подвал используют согласованные контейнеры.

**Практическая проверка:** на узком экране три блока должны идти друг под другом; от `768px` — распределяться по строке. Проверяем переходы из меню и возврат к началу страницы через нижний логотип. Клавишей `Tab` доходим до ссылки и убеждаемся, что фокус виден.

**Вопросы группе с ответами:**

- **Зачем у `h2` класс `h5`?** Смысловой уровень заголовка и его внешний размер решают разные задачи.
- **Почему не поменялись ссылки в меню после переноса `id`?** Их значения сохранены, изменился элемент, которому они принадлежат.
- **За что отвечает `.agenda-footer p`?** За абзацы внутри подвала, а не за все элементы подвала и не за все абзацы документа.
- **Будет ли год обновляться сам?** Нет. Сейчас `2026` — обычный текст в HTML.

**Типичные ошибки:** оставить одинаковый `id` и у старого абзаца, и у новой секции; поставить `aria-labelledby="О проекте"` вместо идентификатора заголовка; изменить общий `.logo-image`, ожидая изменения только нижнего логотипа; перепутать внешний промежуток с внутренним.

## Коммит 7. Исключаю временные предпросмотры из новых изменений Git

**Коммит:** [`ad45290`](https://github.com/FS67-webinars/agenda/commit/ad452903df23fc72961b234a14223846167ae852) — `chore: ignore local previews`.

**Добавлен:** `.gitignore`.

> **Моя цель.** «Во время работы могут появляться временные файлы для просмотра и скриншоты. Я хочу, чтобы такие файлы не попадали случайно в следующие коммиты вместе с исходниками страницы».

В файле записаны следующие правила:

```gitignore
# Local previews and screenshots
/.preview/
/preview/
/previews/
/screenshots/
/preview.*
/preview-*.png
```

`.gitignore` — инструкция для Git. Она не является CSS, не подключается в браузере и не управляет тем, какие изображения видит посетитель страницы. [Официальная документация Git](https://git-scm.com/docs/gitignore) отдельно уточняет: правила игнорирования относятся к файлам, которые ещё не отслеживаются Git; уже отслеживаемые файлы от добавления правила не исчезают из истории и не перестают отслеживаться автоматически.

| Правило | Как читаю | Пример совпадения |
|---|---|---|
| `# Local previews and screenshots` | Комментарий для человека | Ничего не исключает |
| `/.preview/` | Каталог `.preview` рядом с этим корневым `.gitignore` | `.preview/index.html` |
| `/preview/` | Каталог `preview` в корне репозитория | `preview/index.html` |
| `/previews/` | Каталог `previews` в корне | `previews/mobile.html` |
| `/screenshots/` | Каталог `screenshots` в корне | `screenshots/mobile.png` |
| `/preview.*` | Корневое имя, начинающееся с `preview.`; `*` заменяет последующие символы имени | `preview.html` |
| `/preview-*.png` | Корневое имя с началом `preview-` и окончанием `.png` | `preview-mobile.png` |

Начальный `/` привязывает правило к расположению данного `.gitignore`; здесь он находится в корне репозитория. Конечный `/` уточняет, что ожидается каталог. `*` в этих примерах не означает переход через любое число вложенных каталогов.

> «Игнорировать файл — не значит удалить его. Файл может спокойно оставаться у меня на компьютере. Git просто не предлагает добавить подходящий новый файл в обычном списке изменений. И ещё: наличие правила для скриншотов не доказывает, что кто-то уже сделал скриншоты или провёл визуальную проверку».

### Как показываю и проверяю правила

В VS Code открываю `.gitignore`, объясняю каждую строку, затем читаю коммит:

```bash
git show ad45290 -- .gitignore
```

При необходимости проверяю, какое правило соответствует учебному пути, не создавая сам файл:

```bash
git check-ignore -v preview-mobile.png
```

Команда показывает совпавшее правило, если путь не отслеживается и подпадает под игнорирование. После `git status --short` обсуждаем, какие изменения Git предлагает сохранить. Это команды проверки, а не способ автоматически удалить файлы или изменить страницу.

**Что получил:** правила для исключения определённых временных файлов из обычного добавления в Git. **Что не изменилось от этого коммита:** HTML, CSS и содержимое страницы.

**Вопросы группе с ответами:**

- **Удалится ли локальный `preview-mobile.png` после добавления правила?** Нет.
- **Пропадёт ли уже закоммиченный файл из истории?** Нет.
- **Доказывает ли каталог в `.gitignore`, что проверка выполнена?** Нет: правило описывает, что игнорировать, а не фиксирует результат проверки.
- **Могут ли эти правила объяснить отсутствие `docs/HTML_CSS_STAGE_COMPLETE.md` в проверенной ветке?** Нет. Ни одно из приведённых правил этот путь не исключает.

После этого коммита заканчивается рассматриваемая последовательность из семи изменений. Последним коммитом, изменявшим саму страницу, остаётся `10d5c6e`; README и `.gitignore` дополняют работу с проектом.

## Как я показываю историю в VS Code и браузере

### Сначала читаем изменения, не переключая рабочие файлы

Для команд Git нужна локальная копия репозитория с историей. Если проект получен ZIP-архивом, в нём может не быть Git-истории; для демонстрации я отдельно клонирую репозиторий в свободную папку:

```bash
git clone https://github.com/FS67-webinars/agenda.git agenda-history-demo
```

Открываю эту папку в VS Code. Если работаю с уже существующей Git-копией, использую её и не создаю второй клон без необходимости. Команды ниже выполняются из корня выбранного репозитория.

Для получения опубликованных коммитов при необходимости выполняю:

```bash
git fetch origin
```

Эта команда получает историю с удалённого репозитория и обновляет соответствующие удалённые ссылки. Она не сливает ветки и не подменяет текущие рабочие файлы.

Показываю последовательность семи коммитов от исходной точки к завершению рассматриваемой ветки:

```bash
git log --oneline --reverse ab18f454..ad452903
```

`--oneline` даёт короткую строку на коммит. `--reverse` разворачивает порядок: сначала более ранние изменения. Диапазон означает коммиты, доступные из правого состояния и не входящие в левое.

Каждый шаг открываю отдельно:

```bash
git show 7f46686 -- index.html style.css
git show af6ac3c -- index.html style.css
git show 5ef3160 -- index.html style.css
git show 54d468a -- index.html style.css
git show 10d5c6e -- index.html style.css
git show 4d4e9f6 -- README.md
git show ad45290 -- .gitignore
```

Каждая строка — отдельная команда, их не требуется запускать одним блоком сразу. `--` отделяет указание коммита от путей файлов. `git show` выводит сведения о коммите и его изменения относительно родителя. Если Git открыл постраничный просмотр, клавиша `q` возвращает к приглашению терминала.

Общее изменение страницы от исходной точки до последнего коммита HTML/CSS:

```bash
git diff ab18f454 10d5c6e -- index.html style.css
```

Только изменения между первой карточкой и полным каталогом:

```bash
git diff 5ef3160 54d468a -- index.html style.css
```

Полный файл из конкретного состояния можно прочитать без переключения:

```bash
git show 5ef3160:index.html
```

Здесь двоеточие разделяет коммит и путь внутри него. Все команды `log`, `show` и `diff` в этих примерах служат просмотру. Они не переписывают текущий HTML и не меняют ветку.

### Что показываю средствами VS Code

Открываю панель **Source Control / Управление исходным кодом**. При наличии встроенного **Source Control Graph** выбираю нужный коммит, затем файл — так можно увидеть его изменения в редакторе сравнения.

Ещё один штатный путь — выбрать файл в проводнике VS Code и открыть **Timeline / Временную шкалу**, где доступны события истории файла. Названия и расположение панелей зависят от версии и локализации редактора; команды терминала выше дают однозначный способ открыть тот же коммит.

Мне не требуется дополнительное платное расширение. Важно читать обе стороны сравнения: что удалено, что добавлено и какая часть просто переместилась или получила другое форматирование. [Документация VS Code об управлении исходным кодом](https://code.visualstudio.com/docs/sourcecontrol/overview).

### Для браузера создаю отдельную демонстрационную копию

`git show` показывает текст изменений, но не подменяет страницу в браузере. Чтобы открыть промежуточный результат целиком, нужна рабочая папка с файлами именно той версии.

Я использую отдельный **worktree**. Это дополнительная рабочая папка того же репозитория с собственным выбранным состоянием файлов. Основная рабочая копия остаётся на своём состоянии.

Сначала из корня репозитория смотрю:

```bash
git status --short
git worktree list
```

Первая команда показывает незавершённые изменения, вторая — уже созданные рабочие папки. Для новой папки выбираю свободное имя; в примерах ниже оно `agenda-stage-demo`. Если такая папка уже существует, сначала выясняю её назначение, а не удаляю автоматически.

Создаю демонстрационную папку рядом с текущей:

```bash
git worktree add --detach ../agenda-stage-demo ab18f454b448dd4ca4f21d3ddf7f77555284f316
```

`--detach` означает, что в этой дополнительной папке выбрано конкретное состояние по коммиту без привязки к создаваемой ветке. Это удобно для просмотра истории.

Открываю `../agenda-stage-demo` через **File → Open Folder** в отдельном окне VS Code. В браузере открываю `index.html` именно из этой папки. Теперь перед группой исходная незавершённая страница.

Ниже команды выполняю из **исходной папки репозитория**, а параметр `-C` явно направляет Git в демонстрационную папку:

| Что показываю | Команда | Что ожидаю увидеть после обновления страницы |
| --- | --- | --- |
| Исправленная навигация | `git -C ../agenda-stage-demo switch --detach 7f46686` | Заготовки сохранены, адреса меню исправлены |
| Первый экран | `git -C ../agenda-stage-demo switch --detach af6ac3c` | Появился hero перед каталогом |
| Первая карточка | `git -C ../agenda-stage-demo switch --detach 5ef3160` | Джазовая карточка и две прежние заготовки |
| Полный каталог | `git -C ../agenda-stage-demo switch --detach 54d468a` | Три карточки и подпись об учебных данных |
| Завершённый подвал | `git -C ../agenda-stage-demo switch --detach 10d5c6e` | Полная структура страницы |
| README | `git -C ../agenda-stage-demo switch --detach 4d4e9f6` | Внешний вид тот же; в папке появился README |
| Последний рассматриваемый коммит | `git -C ../agenda-stage-demo switch --detach ad45290` | Внешний вид тот же; доступны правила .gitignore |

Перед переключением смотрю `git -C ../agenda-stage-demo status --short`. Для чистого показа не редактирую эту папку. Если во время учебного эксперимента появились изменения, сначала разбираю их и сохраняю нужное; не использую принудительное переключение.

После каждого переключения обновляю одну и ту же вкладку браузера. Путь к файлу остаётся прежним, меняется его содержимое. Если браузер продолжает показывать старые стили, проверяю правильность папки и обновление страницы.

Чтобы вернуться к последнему **состоянию кода**, выполняю:

```bash
git -C ../agenda-stage-demo switch --detach 10d5c6e
```

Чтобы закончить показ на последнем **коммите всей рассматриваемой ветки**, выполняю:

```bash
git -C ../agenda-stage-demo switch --detach ad45290
```

Во втором случае у меня также есть README и .gitignore. Основную рабочую папку при таком показе я вообще не переключал, поэтому возвращать её назад не требуется.

Если временная папка больше не нужна, после закрытия её окна и проверки отсутствия нужных незакоммиченных файлов можно удалить worktree штатной командой:

```bash
git worktree remove ../agenda-stage-demo
```

Команда без принудительных параметров откажется удалять неготовое к удалению рабочее дерево. Я не добавляю `--force` ради обхода этой проверки. [Официальная документация git worktree](https://git-scm.com/docs/git-worktree).

### Оставшаяся небольшая правка: скругление изображения

В `.agenda-card` установлен внешний радиус:

```css
--bs-card-border-radius: 0.9rem;
```

В локальном Bootstrap внутренний радиус изображения задаётся отдельной переменной, которая по умолчанию рассчитывается из общего `--bs-border-radius`:

```css
--bs-card-inner-border-radius: calc(var(--bs-border-radius) - (var(--bs-border-width)));
```

Поэтому изменение только внешнего радиуса карточки не согласует автоматически верхние углы изображения. При условном корневом размере 16 px внешний радиус становится 14,4 px, а внутренний остаётся около 5 px при стандартной рамке 1 px.

Я предлагаю отдельную короткую правку в собственном `style.css`:

```css
.agenda-card {
    --bs-card-color: var(--agenda-ink);
    --bs-card-border-color: #e4dff1;
    --bs-card-border-radius: 0.9rem;
    --bs-card-inner-border-radius:
        calc(var(--bs-card-border-radius) - var(--bs-card-border-width));
    box-shadow: 0 0.4rem 1.2rem rgba(13, 22, 51, 0.08);
}
```

**Это предлагаемое следующее изменение. В семи разобранных коммитах его ещё нет.** Полный CSS в приложении остаётся точной копией рассматриваемой ветки и не содержит этой добавленной строки.

Смысл формулы простой: внутренний угол согласуем с внешним с учётом толщины рамки. После изменения нужно посмотреть верхние углы всех карточек в браузере. Я предпочитаю исправить конкретную настройку, а не без разбора скрывать всё выходящее за границы через `overflow: hidden`: обрезка может затронуть и полезный индикатор фокуса.
